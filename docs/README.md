# Documentation

This directory separates the reusable scaffold manual from documentation owned by
the adopting organization. Keep the boundary intact so template upgrades remain
reviewable and company material has an obvious home.

- [Workflow reference](workflow/START_HERE.md) is maintained with the scaffold.
  It explains repository structure, checks, releases and adoption.
- [Team documentation](team/README.md) belongs to the adopting organization. Use it
  for durable decisions and process that span more than one project or product.
- Board-specific material belongs in `projects/<id>/docs/` and product integration
  material belongs in `products/<id>/docs/`.

Run results, investigation notes and generated reports belong in issues, pull
requests, CI artifacts or an ignored `build/` directory. If evidence must be frozen
for a release, retain it through the [release-storage process](workflow/RELEASE_STORAGE.md)
rather than adding a dated report to this directory.
